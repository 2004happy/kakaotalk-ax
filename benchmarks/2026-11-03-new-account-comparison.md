# 다른 계정의 실제 화면과 NativeAX 비교 — 2026-11-03

## 범위

로그인이 바뀐 현재 Mac 앱에서 본인 방, 짧은 1:1 방, 긴 1:1 방을 사용했다.
실제 이름·대화 본문·링크·이미지는 이 문서에 기록하지 않는다.

**이번 검증에서 에이전트가 새로 보낸 메시지 0건, 작성한 초안 0건.**
화면에 보인 10월 30일·11월 1일의 기존 메시지는 이번 실행에서 생성한 것이 아니다.
조회와 창 조작으로만 비교를 마쳤다.

- A: 제품의 `NativeAX` 메서드. 헬퍼 프로세스에 OS sandbox를 적용했다.
- B: Codex 기본 `cua_repl`로 접근성 트리와 실제 스크린샷을 관찰하고 창 선택·최소화·스크롤을 직접 수행했다.

## 발견하고 수정한 문제

| 문제 | 수정 전 | 0.7.1 수정 후 |
|---|---|---|
| 방이 많은 목록 | AX 테이블의 보고 행 수 464개를 모두 순회하다 `accessibility_control_limit` | `AXVisibleRows`의 현재 7~8개만 읽고 `reportedRowCount=464`를 별도 반환. 약 1.2초에 완료 |
| 긴 방을 포함한 3방 병렬 읽기 | 약 8.0초 후 2방 성공, 긴 방은 `accessibility_read_limit` | 노드의 메타데이터를 한 번에 읽도록 변경. 같은 초기 데이터에서 3방 모두 약 5.4초에 성공 |
| 안 읽은 수가 붙은 시각 | `1\n오후 2:48`을 시각으로 인식하지 못해 null | 시각 줄을 분리해 `오후 2:48`, 해당 날짜를 반환. 작성자는 추측하지 않음 |

메타데이터 일괄 조회에는 Apple의
[AXUIElementCopyMultipleAttributeValues](https://developer.apple.com/documentation/applicationservices/1462051-axuielementcopymultipleattribute)를 사용한다.
필수 본문 읽기 실패는 중단하고, 선택적 속성의 오류는 구분한다. 입력창은 대화 테이블 밖에 있으며
메시지 입력 요소를 발견하면 내용을 반환하지 않고 중단한다.

속도 수치는 해당 데이터에 대한 개별 관찰이다. 모델의 판단 시간·스크린샷·컴퓨터 유즈 왕복을
포함한 동일 조건의 반복 성능 실험이나 일반적인 속도 보장 수치가 아니다.

## 시나리오와 교차 확인

| 시나리오 | 헬퍼 결과 | 컴퓨터 유즈와의 비교 |
|---|---|---|
| 많은 방의 목록 | 보고 행 464개, 현재 보이는 7~8개 반환 | 실제 화면의 방 이름·순서·미리보기와 일치. 검색창을 펼치면 보이는 행 수가 줄어드는 것도 반영 |
| 화면 밖의 본인 방 열기 | 검색으로 본인 배지를 확인하고 정확한 창 열기 | 친구 화면의 본인 프로필과 열린 본인 대화창을 직접 확인 |
| 방 검색 | 본인 이름 검색 시 앱의 보고 행 74개, 없는 검색어는 0개, 해제 후 464개 | 앱 검색은 방 이름뿐 아니라 참여자에도 일치한다. 모든 반환 항목을 이름 부분 일치로 해석하면 안 됨 |
| 긴 방의 텍스트 | 초기 로딩 56행 중 본문 46개 | CUA가 읽은 46개와 순서·정규화한 본문 전체가 일치. 화면의 최근 말풍선도 대조 |
| 3방 병렬 읽기 | 본문 15개·13개·46개를 모두 반환 | 각 방을 별도로 관찰한 데이터와 일치. 방 사이의 원자적 스냅샷은 아님 |
| 이전 대화 요청 | 56행 → 107행, 텍스트 본문 46개 → 92개 | 직접 위로 스크롤해 새로 드러난 본문 4개가 모두 헬퍼의 추가 데이터에 있고, 이전 46개에는 없음을 확인 |
| 실제 창 최소화 | 최소화 상태에서 본인 방 15개를 동일하게 읽음 | CUA로 최소화한 뒤 `minimized=true`를 전후 확인. 읽기 UI 동작 0회, 최소화 유지 |
| 없는 방을 섞은 일괄 읽기 | 정상 2방은 유지하고 없는 1방만 `target_room_window_not_open`, 전체는 `partial` | 현재 열려 있는 대상과 일치. 실패한 방 때문에 정상 결과를 버리지 않음 |
| 본문 검색 | 양성 검색 1건, 없는 문구는 0건 | 양성은 실제 검색창의 검색어·강조된 말풍선과 일치. 음성은 앞서 관찰한 13개 본문에 해당 문구가 없음을 대조했으며, 별도의 0건 UI 표시는 확인하지 않음 |
| 닫기와 다시 읽기 | 창 닫기 성공, 닫힌 창 읽기는 중단 | 방은 메인 목록에 남으며 창만 닫힘 |
| 일괄 자동 열기와 정리 | 닫힌 방만 다시 열고 15개·13개 조회 후 그 창만 닫음 | 원래 열린 최소화 본인 창은 유지. 마지막에는 검증용 대화창을 닫고 메인 검색창을 접음 |

본문 비교에서는 CUA의 링크 마크업과 공백 표현을 정규화한 뒤 본문 순서와 비교용 지문을 대조했다.
원본 바이트 전체가 동일하거나 사진·파일 내용까지 비교했다는 의미는 아니다.
CUA와 헬퍼는 텍스트 관찰에서 같은 macOS 접근성 데이터를 사용하므로, 스크린샷 확인은 별도로 수행했지만
이를 독립적인 서버 기록이나 전체 과거 기록의 검증으로 해석하지 않는다.

## 컴퓨터 유즈에서 관찰한 차이

- 여러 창이 있으면 관찰 도구가 의도한 대화 대신 메인 창이나 다른 대화창을 선택하는 경우가 있었다.
  창 제목을 확인하고 창 메뉴에서 대상을 다시 지정했다. 중간의 잘못된 메뉴 선택도 최신 상태로 복구했다.
- 검증 중 실제 새 수신으로 목록 순서도 바뀌었다. 오래된 항목 번호를 재사용하면 안 된다.
- AX 인덱스를 대상으로 한 스크롤은 화면을 움직이지 않은 경우가 있었고,
  새 스크린샷을 기준으로 대화 영역에 좌표 휠 스크롤을 사용하자 과거 화면으로 이동했다.
  이 좌표 조작은 비교용 CUA 경로에만 사용했으며 제품 헬퍼에는 추가하지 않았다.
- GUI에서는 사진 속 내용·반응·작성자 표시·고정 공지를 볼 수 있었다. 헬퍼는 텍스트 본문 중심으로
  읽으므로 이 정보를 동일한 수준으로 해석하지 않는다. 사진·본문 없는 행을 텍스트 누락과 혼동하면 안 된다.

## 남은 한계와 종료 상태

- 방 목록의 `items`는 전체 464개 목록이 아니다. 전체 보고 행 수와 현재 보이는 항목을 구분한다.
- 최대 AX 노출 1000행, 8초의 네이티브 읽기 제한이 있다. 더 큰 기록·더 높은 병렬 수까지
  이번 결과를 일반화하지 않는다. 전체 모바일 기록·검색 인덱스의 완전성은 보장하지 않는다.
- 창 전환 직후 보조 창이 생성·소멸하는 구간에서는 한 차례 창 목록의 정상 `items`를 얻지 못했다.
  이를 창이 없다는 증거로 쓰지 않고 최종 상태를 별도로 재확인했다.
- 신규 전송과 초안 작성은 이번 계정에서 검증하지 않았다. 이전 버전의 전송 검증과 구분한다.
- 최종 재확인에서 읽을 수 있는 대화창은 0개, 메인 목록 조회는 정상, 보고 행 수는 464개였다.
  검증용 대화창과 메인 검색창을 정리했고 별도 로그인은 하지 않았다.
- 단위 테스트 78개, 스킬 검사, 의존성 검사, `git diff --check` 통과.
  로컬 설치는 0.7.1로 갱신했다. 계정 제재 원인이나 장기 안정성에 대한 실험은 아니다.
