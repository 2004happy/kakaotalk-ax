# NativeAX 0.7 통합 검증 — 2026-11-03

## 정식 헬퍼로 옮긴 기능

`NativeAX`에 방 목록·방 검색·열기·닫기·본문 읽기·여러 방 자동 열기와 병렬 읽기·이전 대화 요청·
본문 검색·검색 종료·전송·전송 결과 조회를 통합했다. 호출자가 별도의 Swift 파일이나 스레드 코드를
작성할 필요가 없다. CLI `ax-call`과 MCP 도구도 동일한 메서드를 호출한다.

네이티브 코드는 패키지의 `ControlKakaoAX.swift`, `ReadKakaoAX.swift`, `SendKakao.swift`다.
창 조작은 프로세스 간 잠금으로 직렬화하고, 여러 방의 본문 읽기는 최대 4개 프로세스로 병렬화한다.
메시지 전송 요청은 디스크에 먼저 기록하고 한 번만 디스패치한다.

## 실제 앱 검증

시험 계정의 나와의 대화와 다른 1:1 방에서 수행했다. 모든 실제 앱 검증의 헬퍼 프로세스에는
macOS sandbox를 적용해 다음을 차단했다.

- 카카오톡 실제 앱 컨테이너의 파일 읽기·쓰기. 디렉터리 접근에서 `PermissionError` 확인.
- 프로세스의 직접 네트워크 통신. 루프백 바인드에서 `PermissionError` 확인.

공식 카카오톡 앱은 sandbox 밖에서 평상시대로 동작했다. 공식 앱의 통신까지 차단하거나 측정한 것은 아니다.

| 기능 | 실제 확인 결과 |
|---|---|
| 방 목록 | 시험 계정의 노출된 방 3개 |
| 앱의 방 검색 | 알려진 이름 1개, 없는 검색어 0개, 빈 검색어로 원래 3개 복구 |
| 목록 밖 방 열기 | 목록을 다른 검색어로 비운 뒤 헬퍼가 대상 이름을 검색·열고 이전 검색어 복구 |
| 본인 방 확인 | AX의 본인 배지를 확인한 뒤 `require_self=True`로 열기 |
| 닫기 | 1:1 창 닫기·다시 닫기의 멱등 결과, 다시 열기 |
| 초안 보호 | 초안이 있는 본인 창의 닫기·전송 중단. 입력값 변경·전송 없음 |
| 일괄 읽기 | 두 방의 본문 10개·13개를 헬퍼 한 호출로 자동 열기·병렬 읽기 |
| 일괄 정리 | 호출이 새로 연 1:1 창만 닫고 원래 열린 본인 창은 보존 |
| 본문 검색 | 앱 검색과 노출 본문 검색 모두 동일 검색어의 2개 항목 반환 |
| 검색 종료 | AX 버튼으로 검색 필드가 사라진 것을 확인 |
| 이전 대화 요청 | 대화 영역의 AX 스크롤바를 최소값으로 이동하는 동작 성공 |
| 실제 전송 | 사용자가 초안을 비운 뒤 본인 방에 일상 문장 1건. 본문 10개 → 11개와 빈 입력창 확인 |
| 중복 방지 | 동일 요청 재호출의 네이티브 전송 호출 0회, 추가 본문 0개 |
| 최종 일괄 읽기 | 전송 후 11개·13개 확인. 창 열기·닫기·정리도 최종 네이티브 소스로 재확인 |
| CLI | `ax-call read_many`로 동일한 두 방 조회 |
| MCP | 방 열기·닫기·일괄 읽기·본문 검색·전송 결과 조회. 완료된 전송을 같은 ID로 호출해 추가 디스패치 0회 |

검색창은 `AXValue`로 화면의 문자열만 바꾸면 앱의 필터가 갱신되지 않았다.
검색 전용 `AXTextField`를 확인하고 `AXFocused` → `AXSelectedTextRange` → `AXSelectedText` →
`AXConfirm`으로 편집하도록 구현했다. 검색 갱신을 650ms 기다린 뒤 결과를 읽는다.
이 과정에서 메시지 입력용 `AXTextArea`는 편집 대상으로 허용하지 않는다.

전송의 `AXPress`는 오류 `-25200`을 반환했지만 재시도하지 않았다. 헬퍼가 새 본문 행 증가·정확한
본문 순서·빈 입력창을 별도로 관찰하여 `observed_in_ax`로 기록했다. 새 메시지는 전체 검증 중 1개뿐이다.
이는 로컬 AX 관찰이며 서버 ACK나 상대방 읽음 확인은 아니다.

## 검증하지 못한 범위

- 이전 대화 요청은 AX 스크롤바 동작까지 성공했다. 시험 계정에서 추가 과거 메시지는 나타나지 않았다.
  추가된 과거 기록을 실제로 회수하는 사례는 이번 시험으로 검증하지 못했다.
- AX가 스크롤 동작을 제공한다고 표시해도 `AXScrollUpByPage`가 오류를 반환하는 경우가 있었다.
  스크롤바가 있으면 최소값 설정을 우선한다. 없을 때는 실제 AX 결과와 `no_scroll_effect_observed`를 반환한다.
  추가 행 미노출을 기록의 끝이라고 간주하지 않는다. `endOfHistory=null`, `historyComplete=false`다.
- 한 번 읽는 범위는 AX에 노출된 최대 1000행이다. `limit`은 메시지 개수가 아닌 행 기준이다.
  본문 검색 반환값도 그 범위에 한정되며 전체 검색 인덱스의 모든 일치 항목은 아니다.
- 작성자·생략된 시각·첨부파일·답장 구조는 아직 완전하게 해석하지 않는다.
- 다른 사람의 방에는 실제 메시지를 보내지 않았다. 장기 계정 안정성·제재 원인·로그인 지속성의 보장은 아니다.

## 코드와 패키지

- 단위 테스트 76개 통과. AX 오류·응답 유실·지연 관찰·중복 요청·초안·페이지·검색·병렬 읽기·
  부분 실패·다른 프로세스의 UI 잠금 충돌을 포함한다. 단위 테스트는 실제 메시지를 보내지 않는다.
- 스킬 검증, `pip check`, `git diff --check` 통과.
- 로컬 editable 설치 0.7.0으로 갱신.
- 깨끗한 임시 소스 복사본으로 wheel 빌드. AX Python 모듈과 Swift 소스 3개의 포함 및 원문 일치 확인.
- 실제 대화 본문·계정 식별자·전송 ID는 이 검증 문서나 단위 테스트 픽스처에 기록하지 않았다.
