# v0.8.0 AX 전용 전환 — 2026-11-03

## 제거한 실행 경로

- SQLCipher 실행, DB 탐색·키 복구·설정·SQL·export와 모든 DB 조회 모듈.
- DB 기반 방 식별·전송 사전 확인·전송 결과 확인 엔진.
- DB를 이용한 미디어 조회·다운로드와 관련 MCP 도구·스킬 인수.
- 이전 LOCO·태블릿·UI 구현과 실험 스크립트. 현 소스와 wheel에는 포함되지 않는다.

`kakaotalk-reader` 명령은 AX CLI의 별칭으로 유지한다. `status`는 AX 창 상태만 읽는다.
전송 중복 방지용 AX 저널과 캐시 경로는 유지하며, 카카오톡의 실제 데이터·설정·로그인 정보는 삭제하지 않았다.
현재 MCP 도구는 `kakaotalk_ax_*` 12개이며, 예전 DB 도구는 등록되지 않는다.

## 확인한 결과

- 단위 테스트 43개 통과. 기존 DB 테스트는 제거하고, DB 의존성 import 차단·이전 CLI 경로 거부 검증을 추가했다.
- MCP의 실제 stdio 연결에서 도구 12개 확인, 제거한 DB 읽기 도구 호출 거부 확인.
- 스킬 검증과 `pip check`, `git diff --check` 통과.
- 로컬 editable 설치 v0.8.0으로 갱신.
- 깨끗한 임시 소스로 wheel을 빌드하고 Python 모듈 4개와 Swift 소스 3개·패키지 초기화 파일의 원문 일치를 확인했다.
  DB·LOCO·태블릿·이전 UI 모듈은 없으며, 현재 Python 환경에서도 import할 수 없다.
- wheel의 Swift 브리지 3개를 별도 빈 캐시에 모두 컴파일했다.
- 실제 앱의 창 목록 읽기를 wheel·MCP·CLI 별칭 경로에서 확인했다.
  헬퍼의 직접 네트워크와 카카오톡 앱 컨테이너 접근을 OS sandbox로 차단했다.
  루프백 bind와 컨테이너 디렉터리 접근이 거부된 상태에서도 창 조회가 정상 완료되었다.
  반환값은 `databaseCalls=0`, `uiActions=0`, `dispatchAttempted=false`였다.

이번 전환 검증에서는 새 메시지·초안을 작성하지 않았고, 검색이나 대화창 열기·닫기·로그인도 하지 않았다.
공식 카카오톡 앱은 sandbox 밖에서 동작한다. 앱 자체의 통신 차단이나 제재 원인 검증은 아니다.
AX 기능의 이전 실제 대화 비교 범위와 한계는 다른 날짜별 기록을 참고한다.
